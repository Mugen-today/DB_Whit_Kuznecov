# Исходные данные, окно плагина и 100 запросов

## Запуск

В поставку включён data/test_datasetA.xlsx. Это исходный файл, а не сгенерированные
взамен строки. SHA256 и стабильное пространство идентификаторов — data/manifest.json.
При новой установке выполните init и up --connections --local-api по README.
manage.py up автоматически собирает одноразовый загрузчик, загружает набор,
добавляет geometry и затем запускает backend/dashboard. Ручной команды импорта
не требуется. Первый запуск длится дольше из-за обработки 141831 исходной строки.

Повторный запуск проверяет метку успешно загруженного файла. Новые дубликаты не
создаются, пользовательские изменения не перезаписываются. Если загрузка оборвалась,
метка ещё отсутствует: повторный запуск добавит недостающие документы по стабильным
ID. Для совместимости с предыдущей ручной загрузкой сохранён namespace test-dataset-a.
Если раньше применялся другой --namespace, не объединяйте такие установки без
проверки идентификаторов: они будут восприниматься как другой набор.

Это разрешённая инициализация исторических данных. Она не меняет правило нового
интерактивного ввода: все четыре обязательные группы в плагине по-прежнему нужны.
Строки без ключей сохраняются в cases; отсутствующие диагнозы, адреса и связи
не выдумываются. Рабочая БД пользователя при разработке не изменялась.

Рекомендуемый путь развёртывания — scripts/manage.py up.
Один docker compose up без административного provisioning и шага seed не является
полным сценарием установки этой поставки.

## Окно

Восстановлена компоновка исходного MongoDB Data Loader: блок подключения из пяти
полей, кнопка подключения, блок коллекций с «Выбрать все», кнопки загрузки и закрытия.
Хост и порт относятся к backend (127.0.0.1:8000). Поле пароля заменено API-токеном.
База Schema и служебный пользователь показаны для ориентира и недоступны для правки.

Новый набор, редактирование и Python-консоль открываются отдельными окнами; основное
окно не занято большим текстовым редактором. Добавлена следующая страница для
последней загруженной коллекции. Одна страница — 100 документов. Установите заново
dist/qgis_mongodb.zip и перезапустите QGIS.

## Запросы

queries/catalog.json содержит описание, исходную команду DOCX и адаптированную
команду для каждого из 100 пунктов. queries/queries.mongosh.js — команды для mongosh;
агрегационные pipeline можно перенести в Compass. Результаты — queries/RESULTS.md.

Ключевые исправления:
- Pdtient → Patient.
- medical_record.chronic_disease → medical_record.chronic_diseases.
- result.side_effect → result["side effect"].
- Удалённый Instances.Focus_point заменён соединением
  Instances.instance → Foci.id_instance.
- Поиск отсутствующего пола (#37): $match пустого результата $lookup вместо $unwind,
  который раньше удалял нужные записи.
- Дубликаты ключа обращения (#58) ищутся по Instances.instance.
- Непустые значения проверяются с $exists: true: один $nin также выбирал отсутствующие поля.
- Убраны старые cursor.count() в пользу countDocuments().
- #45 задаёт интервал допустимой долготы 19..180, а не доказывает нахождение точки
  на территории РФ. Географическая принадлежность требует полигона страны.
- #72 — среднее время с начала лечения до даты расчёта, а не завершённая длительность
  лечения (поля окончания в этой схеме нет).

Дата воспроизводимого расчёта — 2026-11-10T00:00:00Z. Она фиксирована в файле.
Для расчёта на другую дату измените AS_OF; меняющиеся результаты не следует
сравнивать с сохранённым отчётом без учёта этой даты.

В наборе нет Foci и Reception, Therapy содержит строки без идентификаторов и не
пополняет нормализованную Therapy. Пустые агрегаты этих коллекций не подтверждают
отсутствия заболеваний/лечения у реальных людей. Проверки сирот учитывают также
отсутствующие ссылки; ненулевой результат надо читать вместе с полнотой источника.
Большинство значений Gender в Excel рассчитано формулой случайного выбора:
статистика пола отражает тестовый файл, а не подтверждённые клинические сведения.

run.mongosh.js выполняет только подготовленный локальный каталог (не пользовательский
код backend). Для отдельного запуска задайте QUERY_CATALOG, QUERY_OUTPUT,
QUERY_AS_OF и подключитесь к Schema с правом чтения. Он сохраняет полный результат
в BSON Extended JSON; не публикуйте этот файл с индивидуальными данными.
verify_results.py независимо рассчитывает результаты на BSON-снимке Python-кодом.
В поставке сохранён обезличенный итог проверки, полные строки пациентов в отчёт
не включены. Python-консоль плагина остаётся ограниченной; произвольный mongosh JS
и все aggregate pipeline она не выполняет.

В данном файле Patient.passport отсутствует у всех 37662 пациентов (#13 возвращает 0).
При интерактивной правке таких исторических записей обязательные значения надо
ввести явно. Автозагрузка не создаёт фиктивных паспортов для прохождения валидации.
Среднее число случаев на очаг (#89) рассчитано по существующим Foci, включая нулевые
счётчики; при пустой Foci результат пуст, а не выдуманное среднее.

Для #33 при совпадающем возрасте SQL не задаёт порядок между пациентами.
Проверка учитывает это: максимальные возраста и принадлежность исходной выборке
обязательны, совпадение случайного порядка документов не требуется.
