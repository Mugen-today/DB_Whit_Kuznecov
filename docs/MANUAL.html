Первый запуск — новая установка

Нужны Python 3.10+, работающий Docker Engine/Desktop с Compose v2 и QGIS 3.x для плагина. Полная GUI-проверка выполнена с QGIS 3.40.6; минимальная заявленная версия плагина — 3.28. Для самостоятельного запуска тестов нужен также Node.js.

Из папки с docker-compose.yml, PowerShell:

py scripts/manage.py doctor
py scripts/manage.py init
py scripts/manage.py volumes
py scripts/manage.py config --connections --local-api
py scripts/manage.py up --connections --local-api
py scripts/manage.py verify
py scripts/manage.py status

Linux/macOS: замените py на python3. Не копируйте .env.example поверх созданного .env. init создаёт собственные секреты и имена томов; volumes готовит тома новой установки. Сохраните .env: без него нельзя надёжно продолжить работу с прежней БД.

Обновление существующей установки

Сделайте резервную копию и сохраните прежний .env вместе с именами томов. Замените файлы проекта, оставьте прежний .env в корне и выполните:

py scripts/manage.py configure
py scripts/manage.py config --connections --local-api
py scripts/manage.py up --connections --local-api
py scripts/manage.py verify

Не повторяйте init и не используйте down -v. Новые имена томов могут привести к запуску пустой БД вместо старой. configure дописывает отсутствующие секреты, но не исправляет ошибочно введённый существующий пароль и не заменяет старые значения.

QGIS: короткий маршрут

  1. Установите dist/qgis_mongodb.zip через менеджер модулей → установку из ZIP.
  2. Перезапустите QGIS и откройте MongoDB Data Loader.
  3. Введите подключение, профиль и соответствующий токен; нажмите «Подключиться».
  4. Отметьте коллекции и загрузите. Geodata — Point EPSG:4326, остальные — таблицы. Все страницы коллекции загружаются автоматически; пустые таблицы тоже добавляются.
  5. Для изменения используйте обычный буфер правок QGIS и сохранение либо JSON-форму. Для создания — форму нового связанного набора или импорт GPKG.
  6. Для GPKG выберите файл/таблицу, сопоставьте поля, дождитесь проверки всех строк, затем нажмите загрузку. Прогресс можно продолжить после прерывания.
  7. Консоль принимает, например, db.Patient.countDocuments({}) и db.Geodata.find({"geometry.type": "Point"}).limit(10).

Обновляйте backend и плагин вместе. Только переустановка ZIP не обновляет Docker-образ. После восстановления geometry заново загрузите Geodata: memory cache QGIS не перечитывается автоматически.

Импорт и сохранность

  • У GPKG нет общего программного лимита строк/размера нового файла: блок передачи ≤4 МиБ, проверка ≤250 строк, запись ≤25 строк — это размеры шагов, а не всего файла.
  • Есть ограничения формата/отдельных атрибутов, диска и времени; подробности в руководстве.
  • До успешной проверки всех строк импорт в MongoDB не начинается. Затем транзакция охватывает одну исходную строку и её связи; весь файл не является одной транзакцией.
  • Повтор идентичного ввода не создаёт повторные документы по тем же ID. Другое содержимое файла или другие PK не являются автоматической смысловой дедупликацией.
  • Встроенные A+B загружаются insert-only; прежние правки не заменяются. cases — дополнительный архив исходных строк и маркеров, а не одна из 17 пользовательских коллекций.
  • Рабочие тома: mongo_data, mongo_config. Дополнительный том <STORAGE_DATA_VOLUME>_imports хранит GPKG и служебные задания, не документы MongoDB.

Инструкция по эксплуатации GIS-MongoDB 0.8.0

Редакция документации: 11.11.2026. Руководство описывает текущую реализацию, а не первоначальный проектный замысел. README — быстрый вход; практикум — подробные действия; скрипты — устройство исходного кода. Автономная иллюстрированная версия: MANUAL.html.

1. Назначение и основной принцип

Проект связывает нормализованные документы MongoDB с настольной ГИС и dashboard. Пользователь формулирует действие в QGIS либо браузере. Backend определяет проверенную сервером роль, проверяет атрибуты и ссылки, выполняет чтение/запись в MongoDB и возвращает данные в пригодном для клиента виде. Клиент не получает пароли технических пользователей БД и не меняет model.json.

В раннем описании использовались отдельные download/upload. В текущей поставке эти функции объединены в backend/app/modules. Обслуживание ведётся для storage, backend, dashboard и одноразового excel-import. QGIS устанавливается на компьютер пользователя; это не контейнер. В схемах стрелки API означают запрос и ответ, а не копирование всей БД при каждом действии.

Компонент Что делает Чего от него не следует ожидать
storage MongoDB Schema, валидаторы, индексы, пользователи, rs0 Автоматического исправления любых пользовательских ошибок данных
backend Общий коннектор, авторизация, страницы, импорт, геометрия, синхронизация Произвольного Python/JavaScript из консоли клиента
dashboard Фильтры, карта, графики, журнал и запросы через backend Прямого соединения браузера с MongoDB
QGIS Plugin Диалоги, загрузка таблиц/точек, редактор и передача правок Постоянного автономного хранилища вместо MongoDB
excel-import Начальная загрузка встроенных A+B Постоянно работающего сервера и произвольного интерактивного импорта Excel
Дисковый кеш GPKG Части файла, проверенные строки, позиции задания Замены прикладных коллекций MongoDB

Геометрия импортируемого файла читается и преобразуется в backend через pyproj. QGIS декодирует уже подготовленные WGS84 GeoJSON/WKT. Проектная CRS карты QGIS может отличаться от CRS слоя; перепроецирование отображения карты само по себе не меняет сохранённые в MongoDB координаты.

3. Схема и связи

model.json — единственный канонический файл BSON-схем. Названия: Instances, Region, Municipality, Settlement, Street, Building, Placement, Reception, Geodata, Patient, Gender, Social_group, Therapy, Severity, Influence, Foci, Location. cases — отдельный служебный архив, поэтому физически после инициализации можно видеть 18 коллекций.

Стрелка указывает от поля-ссылки к целевому документу. Не переосмысливайте адресные ссылки как обратные: именно Region.municipality → Municipality._id, затем Municipality.settlement → Settlement._id и далее по схеме. Критическая особенность: Foci.id_instance ссылается на Instances.instance, а не просто на _id по догадке. Location.address.geodata указывает на Geodata; Patient сам по себе не содержит точку.

Новые _id и связанные значения генерируются backend. _owner_id ограничивает пользовательские документы; qgis_revision позволяет обнаружить конкурентную правку. _request_hash обеспечивает проверку повторного запроса. Эти метаданные не являются полями, которые пользователь должен сопоставлять с GPKG.

Историческая схема допускает неполноту исходных данных. Поэтому обязательность нового пользовательского ввода задаётся одновременно model.json и бизнес-правилами records/entities. В GPKG список требований приходит из backend; нельзя считать, что required только с _id означает возможность создать пустого нового пациента.

4. Развёртывание и обновление

4.1. Новая учебная установка

Рабочая папка должна содержать docker-compose.yml, backend, storage, dashboard, data и scripts. Запустите Docker. В корне выполните doctor, затем init, volumes, config --connections --local-api, up --connections --local-api, verify и status. Точные команды приведены в README и практикуме. При первом запуске нужны сеть для получения образов/зависимостей, свободный диск под MongoDB и исходные файлы.

init выполняют один раз: существующий .env он не перезаписывает. volumes — явная подготовка новой установки. Compose использует external:false и способен создать отсутствующий именованный том; при обновлении это не доказывает, что подключён нужный прежний том. Всегда сверяйте имена до запуска.

4.2. Что делает up

  1. Проверяет, не используются ли тома старым работающим MongoDB-сервисом.
  2. Останавливает backend на время подготовки хранилища.
  3. Запускает storage и ждёт контейнерной готовности.
  4. provision настраивает replica set, схему, роли, индексы и подготовку геометрии.
  5. verify проверяет фактическую схему, права и служебные подключения.
  6. Собирает одноразовый excel-import и запускает seed для A+B.
  7. Повторно проверяет/дополняет геометрию и пространственный индекс.
  8. С --connections собирает backend/dashboard и ждёт их готовности.

Контейнер storage Healthy означает доступность окончательного mongod и ping. Это отличается от корректности всех ролей/валидаторов и от заполнения источников. Для прикладной проверки нужны verify и успешный seed. Backend /health/ready отдельно проверяет свои технические подключения; /health/live сообщает только о живом процессе.

4.3. Обновление

Остановите пользовательские изменения и сделайте копию. Сохраните прежний .env, точные имена data/config-томов и нужный кеш незавершённого импорта. Разверните новые файлы поверх версии проекта, верните .env, выполните configure → config → up → verify. Перезапустите QGIS после переустановки ZIP. Сравните backend_version с 0.8.0. Не заменяйте .env шаблоном и не используйте init для ремонта старых паролей.

Обычный up — полноценный запуск с подготовкой/seed и сборкой, а не только лёгкий restart. Он может занять время. Миграцию старых опечаток выполняют отдельно через migrate-plan и migrate; эти команды останавливают backend и автоматически не возвращают весь интерфейс в работу — после них нужен обычный up.

5. Историческая инициализация A+B

seed.py читает manifest.json, сверяет SHA256 и ищет маркеры bundled-seed:<digest> в cases. При отсутствии маркера вызывается соответствующий загрузчик. Исходные строки архивируются, документы создаются insert-only: существующие _id не обновляются. Маркер добавляется после успешного этапа. После частичного сбоя повтор помогает дозагрузить отсутствующие документы, сохраняя имеющиеся.

Пропуски источников не выдумываются: паспортов нет в исходном наборе, возраст части B отсутствует. Это исторический bootstrap, а не исключение, которым пользователь может обходить строгий интерактивный ввод.

График показывает восемь основных коллекций после чистой A+B, не скорость сервера. Контрольные числа: Patient/Instances по 41938, Geodata 18509, Location 18532, Therapy/Foci по 4276, Region 4337, Municipality 2707. В cases — 146107 исходных строк и две служебные метки. После пользовательских импортов эти числа растут; после фильтрации/смены роли видимая выборка может быть меньше.

geospatial-index.js выполняется и при уже существующих маркерах. Поэтому восстановление пустой geometry не требует удалять источник или запускать init. Валидная новая geometry — {type:"Point",coordinates:[Longitude,Latitude]}; порядок всегда долгота, широта. Отсутствующая/null/пустая geometry восстанавливается только при корректных координатах. Прежнее пустое значение сохраняется в _previous_geometry; непустая ошибочная геометрия не переписывается молча. Частичный индекс gis_valid_geometry включает только помеченные валидные точки.

6. Доступ и секреты

В QGIS имя само по себе не предоставляет права. Backend сопоставляет Bearer-токен и при наличии X-GIS-User проверяет имя. Переключение профиля сбрасывает прежние управляемые слои/каталог и повторно получает права. Несохранённый локальный буфер нельзя терять незаметно: пользователь решает, сохранить его или отменить.

Уровень Пример Кому выдавать

API-токен QGIS_USER_TOKEN Клиенту QGIS этой роли/владельца
Технический пароль MongoDB USER_PASSWORD, PROCESSOR_PASSWORD Только серверным компонентам

7. Выгрузка и редактирование QGIS

Клиент запрашивает каталог доступных коллекций, затем страницы /v1/collections. Курсор основан на _id; _key представляет идентификаторы разных BSON-типов без неоднозначного преобразования. Размер ответа — не предел коллекции: загрузчик проходит все next. Decimal128/Binary и сложные значения передаются в совместимом JSON/Extended JSON; служебные поля скрываются.

Geodata становится Point EPSG:4326; остальные коллекции становятся таблицами без геометрии. Даже пустая таблица имеет поля схемы. Клиент хранит локальный memory cache. После открытия сохранённого QGIS-проекта данные нужно получить заново: проект не превращает этот кеш в постоянный MongoDB provider.

При сохранении backend проверяет роль, владельца, типы, обязательность изменяемых полей, FK и ревизию. Успех возвращает новую ревизию и согласованные координаты/ geometry; отказ сохраняет буфер для исправления. Пакет до 200 правок атомарен; несколько пакетов одного слоя — не одна общая транзакция. При частично выполненных пакетах сначала выясните подтверждённое состояние, не предполагая откат всего слоя. Создание/удаление строк непосредственно memory provider отключено: создавайте через форму либо импорт; пользовательское удаление документов не предоставлено.

Экспорт в GPKG выполняется штатным «Сохранить объекты как…» QGIS для каждой таблицы/слоя. Пространственная геометрия слоя и строковый атрибут geometry — разные сущности. При повторном импорте выбирайте реальный Point-столбец GPKG через флажок, а не пытайтесь сопоставить текстовый JSON в geometry вместо геометрии таблицы.

8. Новый связанный набор и GPKG

Полный набор требует все четыре группы: местоположение, Instances.date, Patient.passport/age/reg_date, Therapy.date_start/diagnosis. Местоположение — Longitude и Latitude вместе либо все описательные поля пяти адресных коллекций. Location/Foci и ссылки создаёт backend. Полная адресная ветка может не создать точку, если координаты не переданы: наличие адреса не означает выполненное геокодирование.

Для частичного GPKG обязательны поля выбранных сущностей, а не все атрибуты всех 17 коллекций. Therapy требует существующий доступный patient либо Patient той же строки; Geodata может быть единственной сущностью при наличии Point. Для Region/ Municipality/Settlement/Street нужен name, для Building — house; точные требования и типы приходят backend. Генерируемые _id/instance и метаданные не сопоставляются.

Передача идёт блоками ≤4 МиБ в отдельный дисковый том. Проверяются завершённость, SHA256 и структура SQLite. После сопоставления создаётся дисковое задание. Страницы читаются по PK, проверяются и складываются в служебный SQLite. До проверки последней строки ни одна строка задания не импортируется в MongoDB. Ошибки показываются с номерами; ответ ограничивает число описаний, а не число проверяемых строк. Затем пользователь отдельно подтверждает запись кнопкой.

Импорт применяет до 25 строк за шаг, сохраняет позицию после каждой подтверждённой строки. При сбое задания пользователь нажимает продолжение. После перезапуска backend позиция берётся с диска, а не из догадки клиента. Повтор после потерянного подтверждения использует те же ID. Это защита повторной доставки, а не поиск одинаковых пациентов по ФИО/паспорту или одинаковых точек по координатам.

График — расчёт счётчика при пакетах по 25, не замер производительности. 5003 строки могут потребовать 201 пакет. В действительности байтовая граница иногда уменьшает пакет; сервер всегда сообщает реальную подтверждённую позицию.

Сессии привязаны к владельцу/роли. Не меняйте исходный файл во время передачи и сопоставление после частичного импорта. Неактивный служебный кеш истекает через 7 дней; он очищается при начале последующих загрузок. Рабочие документы MongoDB при этой очистке не удаляются. До завершения задания нужен диск и для GPKG, и для подготовленных строк; это не только размер исходного файла.

9. Dashboard, консоль и границы выборки

Главный dashboard кеширует overview на 60 секунд; статистический endpoint имеет свой кеш 15 секунд. После записи проверяйте MongoDB напрямую и учитывайте задержку кеша перед обновлением браузерных показателей.

Главный dashboard строит связанные строки по Instances и показывает карту, графики, журнал и экспорт. Аналитик проходит все страницы overview; user/guest сохраняют интерфейсное ограничение 2500 обращений. Отсутствующий пациент/адрес не превращается в выдуманную связь: интерфейс показывает неполные значения.

Полный анализ и количество точек на экране — разные вещи. В режиме отдельных точек есть пользовательский экранный предел 1000–20000; кластеры получают все подходящие геозаписи из загруженной выборки. Журнал листается по 100 строк. Это не новые пределы GPKG или QGIS-коллекций.

Для полных агрегатов используйте эту консоль с подходящей ролью, а не делайте выводы о полноте старых демонстрационных модулей.

11. Резервирование и восстановление

Каталог storage/backup — место для файлов, не планировщик резервного копирования. Для рабочей установки администратор задаёт периодичность и срок хранения. Копия должна включать БД, защищённый .env, конфигурацию установки и при необходимости кеш активного импорта. Логический dump MongoDB не содержит служебные SQLite-задания. Не копируйте файлы живого WiredTiger обычным файловым копированием.

Ниже — пример ручной логической копии при остановленных прикладных записях; он не выполнялся в среде подготовки, поскольку Docker daemon недоступен. Убедитесь, что в образе есть mongodump и достаточно места в /tmp контейнера. При больших базах администратор выбирает отдельное хранилище копий.

На хосте из корня проекта:

docker compose --profile connections stop backend dashboard
docker compose exec storage bash

Внутри Bash контейнера (это уже не PowerShell):

command -v mongodump
umask 077
mongodump --host 127.0.0.1 --port 27017 \
  --username "$MONGO_INITDB_ROOT_USERNAME" \
  --password "$MONGO_INITDB_ROOT_PASSWORD" \
  --authenticationDatabase admin --oplog \
  --archive=/tmp/gis-backup.archive.gz --gzip
exit

На хосте:

$backupFile = ".\storage\backup\gis-" + (Get-Date -Format "yyyyMMdd-HHmmss") + ".archive.gz"
docker compose cp storage:/tmp/gis-backup.archive.gz $backupFile
Get-FileHash -Path $backupFile -Algorithm SHA256
py scripts/manage.py up --connections --local-api

В этой форме --oplog требует полной копии: не добавляйте --db Schema к данному примеру. Файл содержит административные данные и нуждается в защищённом хранении. Не перезаписывайте единственную предыдущую пригодную копию одним и тем же именем; назначьте имя по дате/установке. Не помещайте её в публичный Git.

Восстановление сначала проверяют на отдельной установке с отдельными томами. Администратор подготавливает её аутентификацию и копирует архив. Базовая команда внутри целевого контейнера — mongorestore с --archive, --gzip и --oplogReplay, аутентификацией к целевой admin. Не используйте --drop против рабочей БД. После восстановления необходимо проверить учётные данные из копии, Schema, количества, связи, геометрию и фактическую готовность сервисов. Полный dump может восстановить прежние пользователи/роли: новый .env не становится автоматически совместим с их паролями. Только успешно проверенное восстановление подтверждает пригодность копии. Данный проект не содержит команды manage.py restore.

Официальные параметры инструментов: mongodump и mongorestore.

4. Определите режим: впервые или обновление

4.1. Если это новая отдельная учебная установка

py scripts/manage.py init

Создаётся приватный .env с уникальными секретами и именами томов. Скрипт не должен перезаписывать существующий .env. Сообщение о существующем файле — повод проверить режим работы, а не удалить файл. Откройте .env локально и найдите имена STORAGE_DATA_VOLUME/STORAGE_CONFIG_VOLUME; сохраните их в закрытой записи вместе с резервной копией .env. Не вставляйте содержимое .env в отчёт.

Далее:

py scripts/manage.py volumes
py scripts/manage.py config --connections --local-api

volumes создаёт отсутствующие data/config-тома указанной установки либо сообщает, что использует существующие. config проверяет объединённую конфигурацию Compose; он не доказывает, что сервер запущен или данные загружены. Ключ --local-api применяют вместе с --connections. Для новой установки выполняйте шаги в этом порядке, чтобы видеть, с какими томами работает проект.

4.2. Если у вас уже есть БД

Не выполняйте init. Сохраните старый .env и резервную копию данных. Замените файлы поставки, оставив прежний .env в корне, затем:

py scripts/manage.py configure
py scripts/manage.py config --connections --local-api

configure добавляет отсутствующие новые секреты, не меняя существующие. Он не исправляет уже имеющийся неправильный пароль и не объединяет две разные БД. До up сверяйте прежние имена томов. Не используйте новые случайные имена как «ремонт»: это может скрыть старую БД за пустой установкой.

6. Разберите переход исходников в MongoDB

Откройте data/manifest.json: здесь указаны имена A/B, контрольные суммы и namespace. Скрипт seed.py проверяет целостность файлов. Для A запускает seed_excel, для B — seed_b. В cases попадают исходные строки/происхождение; в 17 коллекций — нормализованные документы. Существующие документы не заменяются.

В sources могут отсутствовать паспорта и возраст B. Не вводите случайные значения, чтобы сделать исторический набор «полным». Bootstrap сохраняет неполноту источника. Новая интерактивная запись обязана пройти более строгие правила. Поэтому один и тот же неполный источник нельзя автоматически считать корректным новым GPKG-вводом.

Контроль для чистой базы: Patient=41938, Instances=41938, Geodata=18509, Location=18532, Therapy=4276, Foci=4276. После упражнений числа изменятся; сначала зафиксируйте начальное состояние. В MongoDB можно видеть cases сверх 17 коллекций каталога QGIS — это не ошибка количества.

7. Войдите в dashboard

Откройте http://127.0.0.1:8501. Выберите роль и пароль из соответствующей переменной: Главврач/аналитик — ROLE_READER_PASS, пользователь — ROLE_USER_PASS, гость — ROLE_GUEST_PASS. Это не QGIS-токены и не пароль root MongoDB.

Последовательно проверьте четыре вкладки: карту, графики, журнал и экспорт. Установите фильтр и сравните число записей до/после. Для аналитика основная выборка читается полностью; у user/guest интерфейс ограничен 2500 обращениями. Режим отдельных точек имеет собственный экранный предел. Меньшее число точек может означать отсутствие координат, фильтр или режим отображения, а не потерю документов. При большом наборе переключитесь в кластеры.

После изменения данных overview может оставаться в кеше до 60 секунд; дождитесь истечения TTL и повторного выполнения страницы. Для немедленного контроля используйте Mongo-консоль/повторную загрузку QGIS, а не только старую карточку dashboard.

Журнал листается по 100 строк. CSV выгружает текущую фильтрованную выборку, а не только видимые 100 строк. JSON/XML-консоль dashboard ограничивает отдельный запрос до 200 результатов; это другой канал, чем полная выгрузка коллекций QGIS. Демонстрационные spatial/analytics для /v1/tz-query сейчас берут одну страницу экспорта; не используйте их как доказательство полного подсчёта всей БД.

10. Выгрузите все коллекции

Отметьте «Выбрать все» либо нужные флажки. Нажмите «Загрузить выбранные коллекции полностью». Дождитесь завершения, проверьте число ошибок. Во время загрузки клиент читает страницы, а не останавливается на первой странице.

В панели слоёв Geodata имеет геометрию Point EPSG:4326. Patient и другие коллекции представлены обычными таблицами без геометрии — это правильное поведение. Откройте таблицу атрибутов каждого контрольного слоя и сравните количества с MongoDB через countDocuments. Пустая коллекция должна добавляться как пустая таблица.

Служебный _key нужен для адресации документа с любым поддерживаемым типом _id. Не редактируйте _id, _key, instance, qgis_revision. Вложенные структуры/массивы часто видны строкой JSON: это транспортное представление, а не изменение исходного BSON-типа в MongoDB.

11. Проверьте Geodata отдельно

В консоли плагина выполните по очереди:

db.Geodata.countDocuments({})
db.Geodata.countDocuments({"geometry.type":"Point", "geometry.coordinates.1":{$exists:true}})
db.Geodata.find({$or:[{geometry:{$exists:false}},{geometry:null},{geometry:{}}]}).limit(10)

В чистой исходной базе первые два значения — 18509, третий запрос не должен возвращать строки. После импорта абсолютное число изменится, сравнивайте согласованность, а не требуйте всегда 18509.

Проверьте у нескольких объектов четыре вещи: атрибут Longitude, атрибут Latitude, сохранённый JSON geometry и реальную геометрию слоя QGIS. Пример точки:

{"type":"Point","coordinates":[30.3,59.9]}

30.3 — долгота, 59.9 — широта. Не меняйте порядок по привычке из записи «широта, долгота». Надпись CRS проекта в правом нижнем углу QGIS не доказывает, что исходный файл имеет эту CRS.

Если поле geometry старых записей пусто, в терминале хоста:

py scripts/manage.py geometry

Затем заново загрузите Geodata в плагине. Эта команда использует реальные координаты и сохраняет прежнее пустое значение. При неверных/отсутствующих координатах она не создаёт вымышленную точку. Не заполняйте всем объектам [0,0] ради исчезновения предупреждения. Внешне отрисованная backend точка и наличие сохранённого поля в MongoDB — разные проверки, поэтому проверяются обе.

12. Выполните пользовательские запросы

Откройте «Консоль MongoDB». Вставьте запрос в редактор и нажмите выполнение. Редактор отправляет введённый текст, а не всегда стандартный пример.

Задача Запрос
Несколько пациентов db.Patient.find({}).limit(5)
Фильтр и сортировка db.Patient.find({age:{$gte:40}}).sort({age:-1}).limit(20)
Подсчёт без ограничения первой страницей db["Patient"].countDocuments({age:{$gte:40}})
Разные возраста db.getCollection("Patient").distinct("age")
Агрегация db.Instances.aggregate([{$group:{_id:"$patient",n:{$sum:1}}},{$sort:{n:-1}}])
Regex db.Geodata.find({"geometry.type":/^Point$/i}).limit(5)

Пространственный пример, расстояние задаётся в метрах для этого GeoJSON-запроса:

db.Geodata.find({geometry:{$near:{$geometry:{type:"Point",coordinates:[30,60]},$maxDistance:10000}}}).limit(10)

Для поля _id типа ObjectId используйте ObjectId("24-символьное-hex-значение") с настоящим идентификатором документа. Простая строка с теми же символами — другой BSON-тип и может не найти документ. Не копируйте текст заполнителя как ID.

Если результатов больше страницы, нажимайте «Следующая страница результата». pretty() и toArray() поддерживаются как оформление, но не заставляют сервер выдать всю БД одним ответом. Курсор консоли истекает после 15 минут без продолжения. Для повторного полного запроса выполните его заново.

Ошибочный запрос должен показывать ошибку, не создавать пустой «успешный» результат. Не используйте import os, print произвольного Python, $out/$merge или попытки изменить роль в теле запроса. Для проверки прав подключитесь guest и запросите Social_group: ожидается отказ, а не пустая таблица, выдаваемая за отсутствие данных.

13. Создайте учебный связанный набор

Проводите упражнение только в учебной БД. Для новой клинической записи нажмите «Новая запись»; откроется форма «Новый связанный набор» с request_id. Сохраните автоматически созданный request_id и заполните entities. Пример entities:

{
  "Geodata":{"Longitude":30.3,"Latitude":59.9},
  "Instances":{"date":"2026-11-11"},
  "Patient":{"passport":"TRAINING-001","age":25,"reg_date":"2026-11-11"},
  "Therapy":{"date_start":"2026-11-11","diagnosis":["TRAINING"]}
}

Это условные значения для обучения, не клиническая запись реального пациента. Вставьте этот объект вместо entities внутри полного шаблона; не удаляйте request_id. diagnosis — массив, age — число без кавычек, даты — ISO-строки, passport — строка для сохранения ведущих нулей. Нажмите проверку/отправку.

Должны создаться также Location и Foci; Patient–Therapy–Instances и местоположение связываются автоматически. Найдите Patient по TRAINING-001, запишите его _id в закрытом учебном протоколе и проверьте ссылки через чтение. Не вводите ID руками в форме полного набора. Удалите одно обязательное поле и убедитесь, что запрос отклоняется, а не создаёт неполный новый случай. Для нового отличающегося набора нужен новый request_id; повтор прежнего с другим содержимым вызывает конфликт.

Адресная альтернатива требует все пять групп: Region, Municipality, Settlement, Street, Building. В полном режиме нужны все описательные поля этой цепочки: Region.name, Municipality.name, Settlement.name/type, Street.name, Building.house/corpus/edificate/fraction/letters. Числовые поля Building остаются целочисленными по model.json; не подменяйте отсутствующее значение выдуманным нулём. Наличие адреса без координат не даёт точку на карте: геокодирование не реализовано.

14. Подготовьте собственный GPKG

Нужен завершённый файл GeoPackage со стабильным первичным ключом таблицы, например fid. Выбранная геометрия должна быть 2D Point, а CRS — реально определённой. Polygon, LineString, MultiPoint и произвольные 3D-геометрии текущий импорт не поддерживает. Если в файле несколько таблиц, импортируется выбранная, затем можно обработать другую.

В QGIS заранее откройте исходную таблицу и проверьте число строк, тип геометрии, CRS и отсутствие NULL в обязательных полях. Завершите редактирование файла перед передачей. Переименование CRS не заменяет корректное преобразование координат. Для непространственной таблицы достаточно атрибутов; флажок геометрии в диалоге будет недоступен. Не добавляйте ненужные фиктивные координаты.

14.1. Минимальные варианты сопоставления

Что создаём Сопоставляем Что не требуется

15. Выполните пакетный импорт GPKG

  1. В плагине нажмите «Загрузить файл .gpkg в MongoDB».
  2. Выберите файл. Плагин передаёт блоки до 4 МиБ, а backend сохраняет их на диск. Не закрывайте/не изменяйте исходный файл в процессе передачи.
  3. После передачи дождитесь списка таблиц. Выберите нужную и проверьте показанное число строк.
  4. Выберите «Отдельные коллекции — частичное сопоставление» либо полный режим.
  5. Сопоставьте реальные исходные столбцы с целевыми полями. Оставьте ненужные назначения в состоянии «не сопоставлено». PK и служебные поля генерирует backend.
  6. Если нужна Point-геометрия таблицы, оставьте флажок. Не путайте её с текстовым атрибутом geometry, который мог появиться при экспорте JSON из MongoDB.
  7. После паузы ввода примерно 0,7 секунды начинается проверка. Можно нажать «Проверить все строки сейчас». Смена назначения сбрасывает предыдущее подтверждение.
  8. Дождитесь конца всех страниц. Обязательные поля, типы, доступность FK и CRS проверяются сервером. Ошибка последней строки тоже запрещает начало записи.
  9. После успеха нажмите «Загрузить в MongoDB». Наблюдайте «загружено X из N».
  10. Завершение — X=N и сообщение об окончании. Проверьте MongoDB и перечитайте затронутые коллекции в QGIS.

Необязательные значения NULL/пустая строка пропускаются. Обязательное поле от этого не становится необязательным. Если все сопоставленные обязательные атрибуты выбранного Patient пусты, строка отвергается; backend не должен молча импортировать только её точку.

4 МиБ, 250 проверяемых строк, 25 записываемых строк — размеры шагов. Это не общий предел файла. В тесте 5003 строки прошли из файла 43589632 байта. Размеры отдельных ячеек/строк и тип геометрии всё равно ограничены; без свободного диска продолжение невозможно. Неисправность «1..1000 rows» означает старую версию backend или плагина.

16. Продолжите прерванный импорт

Если окно закрыто или связь пропала, не создавайте сразу новый отличающийся файл. Вновь откройте диалог под тем же подключением/владельцем и нажмите «Продолжить после прерывания». Плагин восстановит сохранённое задание. Сервер определит, сколько строк действительно подтверждено; число последней надписи на экране может отставать от последнего завершившегося запроса.

При paused прочитайте номер и причину: например, FK перестал быть доступным после проверки. Исправьте причину и продолжите тот же job. Подтверждённые строки не откатываются, непрошедшая строка не пропускается. Повтор завершённого задания не добавляет те же документы заново.

Это не дедупликация любых похожих файлов. Новый файл с другим содержимым или другими PK может породить новые документы. Не меняйте сопоставление во время частичного импорта ради «дозагрузки»: прежние ID с другим содержимым дадут конфликт. Через 7 дней неактивности служебная сессия истекает; выберите файл заново, сохраняя понимание уже записанных документов. В отчёт можно записывать job_id, но не токены.

17. Отредактируйте данные и проверьте синхронизацию

Выберите свой учебный Patient и включите обычное редактирование таблицы QGIS. Измените age, сохраните. Выполните find по _id или тренировочному passport и проверьте значение в MongoDB. При необходимости загрузите слой заново и сравните. Затем отдельно проверьте изменение Longitude: backend должен согласовать geometry.

Вложенные объекты и массивы удобнее изменять JSON-формой «Изменить выбранную». Выберите ровно одну запись. Не удаляйте служебные идентификаторы и не меняйте qgis_revision. Не открывайте одновременно независимые правки одного документа, не понимая конфликтов: старый номер ревизии приводит к 409 и требует сверки.

Для учебной проверки откажитесь от некорректного возраста 140: сервер должен отклонить сохранение, а буфер остаться редактируемым. Исправьте значение, затем повторите сохранение. У аналитика/гостя слой должен быть только на чтение. Карандаш QGIS не должен служить способом обойти роль.

Обычное добавление/удаление строк memory provider не предусмотрено. Не путайте удаление слоя из проекта с удалением документа MongoDB: первое убирает локальное представление, второе API вообще не предоставляет.

18. Экспортируйте пространственные и непространственные данные

В панели QGIS выберите слой/таблицу → экспорт → «Сохранить объекты как…» → GeoPackage. Назначьте файл и уникальное имя таблицы. Проверьте, не включён ли экспорт только выбранных объектов, если требуется всё содержимое. Для Geodata сохраняйте корректную CRS; для Patient не добавляйте искусственную геометрию.

Откройте полученный GPKG как новый источник в QGIS. Сравните число строк с исходным слоем, проверьте несколько полей и Point. Несколько коллекций можно сохранять разными таблицами в одном GPKG, добавляя таблицы, а не перезаписывая случайно весь файл. Такое копирование не превращает GPKG в постоянно синхронизируемую реплику MongoDB: дальнейший импорт — отдельное действие со своими правилами.

Каталог GET /v1/collections Схемы и разрешённые коллекции records.catalog
Страница GET /v1/collections/Geodata?limit=200 Записи/геометрия/next; следующий запрос использует after records.page + geometry

Состояния задания: validating — проверка; invalid — найденные ошибки запрещают запись; ready — всё проверено; importing — применяются строки; paused — нужно исправить причину/повторить; complete — applied=total. Номер upload_id относится к файлу, job_id — к конкретному заданию с сопоставлением; это разные идентификаторы.

Для ручной read-only проверки подключения в PowerShell можно временно прочитать только нужный токен из собственного .env, не печатая его:

$token = (Get-Content .env | Where-Object { $_ -like 'QGIS_USER_TOKEN=*' }) -replace '^QGIS_USER_TOKEN=', ''
$headers = @{ Authorization = "Bearer $token"; 'X-GIS-User' = 'qgis-user' }
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/v1/session' -Headers $headers
Remove-Variable token, headers

Пример рассчитан на стандартный .env, созданный init, с незаключённым в кавычки значением QGIS_USER_TOKEN. Не подставляйте здесь пароль root. Отправлять токены в URL или демонстрировать строку $token преподавателю не требуется.
