# GIS-MongoDB 0.8.0 — пакетный импорт без общего лимита строк

## Обновление существующей установки

Сохраните рабочий .env и существующие тома. Замените файлы проекта и выполните:

```powershell
py scripts/manage.py configure
py scripts/manage.py up --connections --local-api
py scripts/manage.py verify
```

Linux/macOS: python3 вместо py. Не повторяйте init и не выполняйте down -v.
Переустановите dist/qgis_mongodb.zip в QGIS и полностью перезапустите QGIS.
Обновлять нужно и backend, и плагин: в окне подключения должна отображаться версия 0.8.0.
Имена и содержимое прежних mongo_data/mongo_config сохраняются. Для временных файлов
и прогресса добавлен отдельный дисковый том `<STORAGE_DATA_VOLUME>_imports`.
Он не заменяет тома MongoDB. Хранение больших файлов больше не упирается в /tmp tmpfs 128 МиБ.

## Причина ошибки и исправление

В прежнем backend была проверка `1 <= rows <= 1000`; она ограничивала всю таблицу,
а не пакет. Кроме того, build() создавал список всех строк в RAM, вычислял SHA256
чтением всего файла и повторял полный разбор/валидацию при каждом apply по 25 строк.
Плагин отдельно читал файл целиком и отклонял размер больше 32 МиБ.

Эти общие ограничения удалены. Текущий путь:

| Этап | Объём одного шага | Общий объём |
|---|---|---|
| Передача QGIS → backend | До 4 МиБ | Без заданного общего лимита файла |
| Чтение/валидация SQLite | До 250 строк; также ограничено памятью страницы | Все строки выбранной таблицы |
| Запись MongoDB | До 25 строк; также ограничено размером данных пакета | Все успешно проверенные строки |

Количество пакетов не ограничивается. Количество строк и размер пакета — разные
величины. Требуются свободное место на диске и достаточное время выполнения.
Сохранены ограничения структуры: 2D Point либо непространственная таблица,
стабильный ненулевой PK, корректный CRS, атрибуты по схеме и бизнес-правилам.
Один выбранный атрибут ограничен 1 МиБ, выбранные значения одной строки — 2 МиБ;
это защита от гигантских ячеек, не предел файла или таблицы. Дополнительные
ограничения отдельных полей задаёт схема (например, длина текста/число элементов).
Неиспользуемые столбцы и BLOB не загружаются в RAM.

## Как импортировать

1. Подключитесь как qgis-user/admin с правом записи.
2. Нажмите кнопку загрузки GPKG и выберите файл. Передача идёт частями с прогрессом.
3. Выберите таблицу, режим и сопоставление полей. Необязательные поля можно пропустить.
4. Плагин последовательно проверит все строки. До успешного окончания проверки
   записи в MongoDB не начинаются. Ошибка в последней строке тоже блокирует импорт.
5. Нажмите «Загрузить в MongoDB». Отображается фактически подтверждённое число строк.
6. При разрыве связи или закрытии окна вновь откройте импорт и нажмите
   «Продолжить после прерывания». Сохранённая сессия привязана к подключению,
   владельцу и роли. После перезапуска backend прогресс остаётся на диске.

Исходный GPKG при передаче не должен изменяться. При изменении файла выберите его
заново. Плагин не сохраняет API-токен в настройках сессии импорта; сохраняются
идентификатор задания и путь/размер/время изменения исходного файла.
Не меняйте сопоставление посреди частично выполненного импорта: для продолжения
используйте прежнее задание. Конфликт старого request_id с другим содержимым
отклоняется вместо перезаписи ранее созданных документов.

## Проверка, хранение и восстановление

- Проверка выполняется курсорами по первичному ключу, включая составной PK,
  без растущего OFFSET и без полного reread на каждый пакет.
- Валидированные строки и позиция курсора сохраняются в служебном SQLite-задании
  на диске. Это промежуточное состояние ETL; прикладные данные остаются в MongoDB.
- Все строки проверяются до первого apply. Ошибки возвращаются с номером строки;
  для ответа хранятся первые 100 описаний и общее число ошибок.
- При записи одна исходная строка и её связанные сущности создаются транзакцией.
  Весь файл не является одной транзакцией. Ранее подтверждённые строки при сбое
  сохраняются; прогресс фиксируется после каждой строки.
- Идентификаторы детерминированы по файлу, таблице, PK и владельцу. Если MongoDB
  успела записать строку, а подтверждение потерялось, повтор не создаёт дубль.
- При изменении доступности FK после проверки импорт приостанавливается на
  проблемной строке; последующие строки не пропускаются.
- Неактивные временные загрузки и задания истекают через 7 дней. Продолжение
  обновляет срок. Истёкший служебный кеш очищается при следующем начале загрузки;
  документы MongoDB и исходные пользовательские файлы при этом не удаляются.
- Новый интерфейс использует /v1/gpkg/uploads и /v1/gpkg/jobs. Старые /upload,
  /validate, /apply оставлены для совместимости. Прежний предел 32 МиБ остаётся
  только размером одного запроса старого /upload, а не нового файла из QGIS.

## Geodata: geometry в MongoDB

Свежая инициализация A+B создаёт 18509 Geodata с сохранённым GeoJSON Point.
Чтение геометрии для карты и наличие поля geometry в документе — разные проверки.
Скрипт geospatial-index.js теперь восстанавливает отсутствующую/null/пустую geometry
из корректных Longitude/Latitude, включая `{}` и Point с пустыми координатами.
Прежнее пустое значение сохраняется в `_previous_geometry`. PK, FK, координаты и
остальные атрибуты не меняются. Непустая ошибочная пользовательская геометрия не
перезаписывается молча. Если координат нет или они некорректны, точка не выдумывается.

Восстановление выполняется автоматически при up, даже если исходные A+B уже
отмечены как загруженные. Для отдельно обновлённого работающего проекта:

```powershell
py scripts/manage.py geometry
```

После этого заново загрузите Geodata в QGIS: уже загруженный memory cache сам
не перечитывает изменённые документы. В консоли для доступной роли можно проверить:

```javascript
db.Geodata.countDocuments({})
db.Geodata.countDocuments({"geometry.type": "Point", "geometry.coordinates.1": {$exists: true}})
db.Geodata.find({$or: [{geometry: {$exists: false}}, {geometry: null}, {geometry: {}}]}).limit(10)
```

В свежей базе первые два счётчика равны 18509, последний запрос не возвращает строк.
model.json и оба исходных набора сохранены без изменения.
