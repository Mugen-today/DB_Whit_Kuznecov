# Версия 0.7 — 11.11.2026

## Данные и обновление

Сохраните прежний .env, имена STORAGE_DATA_VOLUME/STORAGE_CONFIG_VOLUME и резервную копию.
Не запускайте init повторно и не используйте down -v. Выполните configure, затем
up --connections --local-api и verify. Рабочие данные не удаляются. Первичные
наборы A/B неизменны, повторный managed seed сохраняет пользовательские изменения.
model.json сохранён без изменения названий, BSON-типов и связей 17 коллекций.
Foci.id_instance ссылается на Instances.instance; это не другое имя Patient._id.

Для отдельных владельцев задайте backend-переменную QGIS_IDENTITIES_JSON:

Секрет задаётся только на сервере; имя в QGIS должно соответствовать токену.
Смена профиля инвалидирует старые запросы, права и управляемые слои.

## Выгрузка и BSON

Клиенты проходят все курсоры; 200 записей/примерно 1,5 МБ — размер страницы,
а не предел коллекции. Dashboard запрашивает страницы до 1000; роль reader проходит
их все, обычные профили dashboard сохраняют прежний предел 2500. Данные загружаются
в память клиентов; доступная RAM остаётся естественным ограничением.
_id разных BSON-типов имеет непрозрачный _key для корректной пагинации и редактирования.
Decimal128/Binary и другие сложные BSON значения передаются Extended JSON.
Служебные поля владельца/хешей не выдаются. Изменяемые геометрии — 2D Point WGS84.

## Консоль

Поддержаны find(filter, projection).sort(...).skip(...).limit(...), aggregate,
countDocuments, distinct. В консоли QGIS кнопка продолжения получает следующие
страницы; отсутствие limit или limit(0) не ограничивает общее число строк.
Примеры:

```javascript
db.Patient.find({age: {$gte: 60}}).sort({age: -1})
db.Patient.countDocuments({})
db.Patient.distinct("gender")
db.Instances.aggregate([{$group: {_id: "$patient", n: {$sum: 1}}}])
db.Geodata.find({geometry: {$near: {$geometry: {type: "Point", coordinates: [30, 60]}, $maxDistance: 10000}}})
db.Geodata.aggregate([{$geoNear: {near: {type: "Point", coordinates: [30,60]}, distanceField: "distance", spherical: true, maxDistance: 10000}}])
```

ObjectId, ISODate, Date, NumberLong/Int/Decimal, Extended JSON, True/False/None,
Date.now() и простая арифметика литералов разбираются без eval/exec. Это ограниченный
язык запросов чтения, не произвольная Python/JavaScript-консоль. Прямые MongoDB-команды записи, $out/$merge,
$where/$function/$accumulator запрещены. $lookup и вложенные pipeline соблюдают
права и владельца. Старые create_record/update_record остаются проверяемыми
backend-операциями записи, доступными только user/admin. Курсор привязан к владельцу/роли, живёт 15 минут.
Для пространственных запросов backend добавляет признак валидной геометрии,
соответствующий частичному 2dsphere-индексу gis_valid_geometry. Старые ошибочные
геометрии сохраняются, но не попадают в пространственный поиск.

## Импорт и редактирование

GPKG: файл до 32 МиБ, 1–1000 строк одной выбранной таблицы; геометрия 2D Point
или непространственные атрибуты. Нужен стабильный первичный ключ. CRS проверяется
по метаданным и заголовку геометрии; неизвестный CRS отклоняется. Преобразования
выполняет pyproj в backend с always_xy. Перед записью проверяются все строки.
Частичное сопоставление означает выбор сущностей, а не пропуск их обязательных полей:
Patient требует passport/age/reg_date, Instances.date, Therapy.date_start/diagnosis/patient,
Geodata — согласованные координаты/геометрию. Ссылки должны вести на доступные документы
или сущности той же строки. Полный связанный режим по-прежнему требует четыре группы.
Пакеты по 25 строк, транзакция на строку; при сбое ранее записанные строки сохраняются,
повтор с тем же файлом/таблицей/сопоставлением идемпотентен. Изменение запроса с тем же
идентификатором возвращает конфликт, а не перезаписывает предыдущую загрузку.

Правки QGIS проверяются по ревизии. До 200 правок одного API-пакета выполняются атомарно;
несколько пакетов одного слоя не являются одной общей транзакцией. При ошибке буфер
остаётся в QGIS. Серверная ревизия и согласованная геометрия возвращаются в слой.
Для старых документов проверяются изменяемые атрибуты, без выдумывания пропущенных
исторических значений. Пользовательское удаление документов не предоставляется.

## Docker

Конфигурация Compose и сохранение прежних имён томов проверяются отдельно от запуска.
В среде подготовки Docker socket недоступен; успешный запуск контейнеров не заявляется.
На машине с Docker выполните manage.py integration: сценарий использует отдельный проект
и тестовые тома. Рабочую установку проверьте manage.py verify после обновления.
