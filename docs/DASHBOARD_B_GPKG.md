# Обновлённый dashboard, test_B и импорт GeoPackage

## Обновление

Сохраните существующие .env и Docker-тома. Замените файлы проекта и выполните:

```powershell
py scripts/manage.py configure
py scripts/manage.py up --connections --local-api
py scripts/manage.py verify
```

Linux/macOS: python3 вместо py. configure добавляет только отсутствующие настройки;
новые пароли профилей dashboard: ROLE_READER_PASS, ROLE_USER_PASS, ROLE_GUEST_PASS.
Их значения находятся в вашем .env. Предустановленных admin123/user123/guest123 нет.
Пароли и локальный .env из присланного архива в поставку не перенесены.

Откройте http://127.0.0.1:8501 и войдите под выбранным профилем. Dashboard использует
токен соответствующей роли при каждом запросе; переданный в URL/JSON role не повышает
права. Аналитик читает доступную базу, пользователь работает со своими документами,
гость не читает Social_group, Street, Building, Placement. Индивидуальные учётные
записи врачей пока не реализованы: пользовательский токен представляет qgis-user.

Перенесены четыре вкладки, фильтры, карта, графики, журнал, CSV/GeoJSON и консоль
JSON/XML. Запросы ограничены 200 документами. Карта, фильтры, графики и CSV работают
по выборке до 2500 обращений; общий счётчик обращений считается по доступной базе.
Это ограничение показано в интерфейсе; обещание выгрузки 100000 строк удалено.
Скрытие отдельных полей в гостевом интерфейсе не является заявлением о юридически
полной анонимизации всей системы.

## Два источника

data/test_datasetA.xlsx и data/testB_normalized.json входят в поставку.
SHA256 обоих файлов закреплён в data/manifest.json.
Команда up сначала инициализирует Storage, затем загружает оба источника и только
после этого запускает backend/dashboard. Каждый источник имеет свою метку успешной
загрузки. Старый Excel повторно не перезаписывается; test_B добавляется независимо.
Повторный запуск сохраняет правки и не создаёт новые копии уже загруженных строк.

test_B содержит 4276 записей. Для каждой создаются Patient, Therapy, Instances,
Geodata, Location, Foci и Region. Municipality создаётся только при наличии значения.
Числовые/логические поля берутся из источника, неизвестные возраст/паспорт/пол не
заполняются предположениями. Исходный JSON каждой строки целиком сохранён в cases.
Поле Instances.date сопоставлено с patient.reg_date из источника. Пространственные
данные берутся из GeoJSON location; они совпадают с foci.geodata исходного файла.
Адрес сохраняется в Therapy.other; режим химиотерапии — в treatment_procedures.
Признак смерти переносится как Saved=false только при явно указанном died_tb либо
died_other. Отсутствие этих признаков не выдаётся за доказанное выздоровление.
Флаги и симптомы, которым нет однозначного соответствия в текущей схеме, остаются
в исходном архиве cases.

Это импорт исторических наборов, а не обход правил пользовательского ввода.
Новая запись из QGIS по-прежнему требует все четыре обязательные группы.
Пациенты в двух источниках без общего надёжного идентификатора не объединяются
по адресу/датам. Справочные адресные сущности test_B создаются по записи: количество
документов Region не равно числу уникальных названий регионов.

## Импорт .gpkg из QGIS

Переустановите dist/qgis_mongodb.zip и перезапустите QGIS.

1. Откройте MongoDB Data Loader, задайте backend и пользовательский API-токен.
2. Нажмите «Загрузить файл .gpkg в MongoDB».
3. Выберите файл и таблицу. Backend вернёт список исходных полей.
4. Сопоставьте поля источника с полями MongoDB. Можно использовать одно поле
   источника для нескольких целевых полей (например, для дат), если это осмысленно.
   Пустое сопоставление означает «не передавать», а не подстановку значения.
5. Для пространственной таблицы можно использовать её 2D Point-геометрию. Backend
   читает CRS и преобразует координаты через pyproj в WGS84 с порядком longitude/latitude.
   Либо отключите геометрию таблицы и сопоставьте Longitude/Latitude явно.
6. Нужны все четыре группы: координаты или полный адрес; Instances.date;
   Patient.passport/age/reg_date; Therapy.date_start/diagnosis.
   diagnosis принимает строку (один диагноз) или JSON-массив строк.
7. Нажмите «Проверить все строки». При ошибке получите номер строки и причину.
   До успешной проверки всех строк ничего не записывается.
8. Нажмите «Загрузить в MongoDB». Ключи и ссылки создаются backend, одна строка
   файла становится полным связанным набором в одной транзакции.

Ограничения текущей реализации: до 32 МиБ, до 1000 строк в выбранной таблице;
обычные таблицы features/attributes со стабильным первичным ключом. Поддерживаются
2D Point; Polygon, LineString, Z/M и неизвестный CRS отклоняются, не превращаются
неявно в центроид. Атрибутивную таблицу можно загрузить при наличии обязательных
координатных или адресных полей. Геообработка на стороне QGIS не выполняется.

Запись идёт пакетами по 25 строк; транзакция охватывает один связанный набор,
а не весь файл. Если в процессе записи произошёл сетевой/серверный сбой, предыдущие
успешные строки могут остаться. Повторите тот же файл: стабильные request_id
предотвращают дубли. Изменение сопоставления для уже записанной строки того же
файла вызывает конфликт 409 вместо создания второй копии. Для корректировки
используйте редактирование записей. Успешный повтор не отменяет последующие правки.

Файл хранится только во временной области backend; загрузка действует один час и
привязана к владельцу. При перезапуске backend выберите файл снова. Суммарное место
под файлы ограничено 96 МиБ. Файл не передаётся напрямую в MongoDB и не читается
библиотеками QGIS: все проверки, преобразования типов/CRS, разбор геометрии и запись
выполняются backend.

Для дат GeoPackage поддерживаются ISO-форматы и ДД.ММ.ГГГГ (также с часами/минутами); backend преобразует их перед строгой проверкой. Преобразования CRS без доступной точной операции/необходимых сеток отклоняются вместо неявного приближения.
