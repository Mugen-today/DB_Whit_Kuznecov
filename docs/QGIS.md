# Плагин QGIS и MongoDB

В этой версии плагин работает с точечными документами `Schema.Geodata` через HTTP backend. В QGIS применяется стандартный memory provider. Данные показываются в EPSG:4326, координаты передаются в порядке долгота, широта.

Пользователь может загрузить страницу точек, создать новую точку, выбрать точку и изменить её координаты или высоту. Сохранение подтверждает backend после записи в MongoDB. Изменение точки не создаёт связанный Patient, Instances или Foci. Для таких предметных сущностей остаётся отдельный импорт существующего проекта.

## Запуск сервера

Новая установка на Windows

```powershell
py scripts/manage.py init
py scripts/manage.py up --connections --local-api
```

Если `.env` уже существует, выполните вместо init

```powershell
py scripts/manage.py configure
py scripts/manage.py up --connections --local-api
```

На Linux/macOS используйте python3 вместо py. Configure добавляет отсутствующие `QGIS_USER_TOKEN` и `QGIS_GUEST_TOKEN`. Пустые существующие значения нужно заменить случайными токенами вручную. После изменения `.env` перезапустите backend через up. Пароли MongoDB и API-токены имеют разные назначения.

Плагин обращается к http://127.0.0.1:8000 . Проверьте в браузере `/health/ready`. Для удалённого сервера необходим HTTPS и собственная защищённая публикация backend. Штатная конфигурация публикует порт только на localhost.

## Установка в QGIS

Поддерживается QGIS 3.28–3.44. Фактический тест проведён на QGIS 3.40.6.

1. Распакуйте общий архив проекта.
2. Откройте QGIS, затем «Модули → Управление и установка модулей → Установить из ZIP».
3. Выберите `dist/qgis_mongodb.zip`, находящийся внутри проекта.
4. Включите модуль **GIS MongoDB Backend**.
5. В меню модулей откройте **GIS MongoDB → MongoDB через backend**.
6. Укажите адрес backend и токен из соответствующей переменной `.env`.
7. Нажмите «Загрузить».

Для самостоятельной сборки устанавливаемого ZIP

```powershell
py scripts/package_plugin.py
```

MongoDB, PyMongo и библиотеки backend устанавливаются на стороне сервера. Плагин использует библиотеки, поставляемые с QGIS. API-токен сохраняется только в памяти открытого окна. В QSettings сохраняется адрес сервера.

## Выбор доступа

`QGIS_GUEST_TOKEN` даёт чтение всех документов Geodata с корректными координатами. Это удобный режим для просмотра ранее импортированных данных.

`QGIS_USER_TOKEN` даёт создание точек и чтение/изменение точек, принадлежащих серверному пользователю `qgis-user`. Документы прежних импортов без `_owner_id` в этом режиме не отображаются. Пустой слой при первом подключении с пользовательским токеном допустим. Создайте точку, чтобы проверить запись.

Выбран простой вариант подключения одного пользователя. Все операторы с одним QGIS_USER_TOKEN работают от одной идентичности `qgis-user`. Для разных личных пользователей понадобится отдельная серверная аутентификация и выдача токенов с индивидуальной идентичностью. Роль и идентификатор владельца определяет сервер по токену.

Новые маршруты плагина проверяют токен и владельца. В приложенной объединённой ветке прежние `/v1/query`, импорт и обзор сохраняют существующую модель доступа. Перед сетевым развёртыванием вне доверенной локальной машины требуется единая авторизация всего API.

## Загрузка и сохранение

За запрос показывается до 200 документов. «Следующая страница» заменяет слой очередной страницей. Счётчик пропусков показывает документы текущей страницы без допустимых координат. Исправление пропущенных исходных данных выполняется отдельно.

Для создания введите долготу, широту, необязательную высоту и нажмите «Создать точку». После успешной записи слой покажет подтверждённую сервером точку. «Загрузить» возвращает общий список. При потере ответа повторное нажатие с теми же значениями повторно использует request_id и получает прежний документ. При намеренном создании следующей точки после подтверждённого успеха используется новый request_id.

Для изменения выберите одну точку стандартным инструментом выделения QGIS и нажмите «Изменить выбранную». В открывшемся окне задайте координаты и высоту, затем сохраните. При конфликте ревизии backend вернёт 409. Загрузите актуальный слой и повторите изменение. Перед новым изменением после смены подключения также требуется загрузить слой.

Обычное редактирование memory-слоя отключено. Изменение выполняется кнопкой плагина, которая ожидает ответ backend. Это предотвращает ситуацию, когда локальное сохранение QGIS ошибочно принимается за подтверждённую запись MongoDB. Удаление документов через плагин отсутствует. Исходные cases остаются сохранёнными.

Высота хранится в Elevation без вертикального преобразования. Схема не задаёт вертикальный датум, поэтому его нужно согласовать для реальных данных.

## Provider Architecture и DB Manager

Слой создаётся через `QgsVectorLayer(..., "memory")`, `QgsFeature` и `QgsGeometry`. Это стандартная архитектура провайдеров QGIS. Сетевые операции используют асинхронный `QgsNetworkAccessManager` с настройками прокси QGIS, таймаутом и обработкой ошибок. Запросы не блокируют интерфейс ожиданием ответа.

Встроенный DB Manager поддерживает GeoPackage и другие пространственные СУБД. MongoDB не входит в заявленный список встроенных подключений. Кнопка **GeoPackage** сохраняет текущую страницу в файл через `QgsVectorFileWriter`. Файл можно открыть через Browser или DB Manager. Изменения такого файла хранятся локально и не отправляются автоматически в MongoDB.

## Маршруты backend

| Метод | Маршрут | Действие |
|---|---|---|
| GET | /v1/qgis/points?limit=200&after=ObjectId | Страница точек с серверным фильтром владельца |
| POST | /v1/qgis/points | Создание точки с UUID request_id |
| PUT | /v1/qgis/points/ObjectId | Изменение координат с проверкой revision |

Bearer-токен передаётся в заголовке Authorization. Координаты должны быть конечными числами в диапазонах WGS84. Тело записи ограничено 8 KiB. Ответ содержит mongo_id и revision. Изменение выполняется атомарно с условиями на ObjectId, владельца и ревизию.

## Проверки

Обычный `manage.py integration` дополнен проверкой HTTP-маршрутов плагина на отдельной базе. Для PyQGIS предусмотрен `tests/integration/qgis_actions.py`. Он требует настоящие QGIS, PyMongo и отдельный тестовый backend с переменными окружения из тестовой конфигурации. Сценарий намеренно пишет учебные документы. Запускайте только с `ISOLATED_STORAGE_TEST=1` в изолированной базе.

Фактически выполненные проверки перечислены в tests/VERIFICATION.md.
