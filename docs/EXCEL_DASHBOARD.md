# Excel и дашборд: запуск и проверка

## Обновление существующего проекта

Распакуйте новую версию в отдельную папку и перенесите туда вашу существующую `.env`. Не запускайте `init` для существующей базы: эта команда предназначена для новой установки. Имена volumes и пароли должны остаться прежними. Остановите старый стек без удаления volumes, если запускаете проект из другой папки. Не используйте `down -v`.

Из корня проекта (Windows: `py`, Linux/macOS: `python3`):

```bash
python3 scripts/manage.py configure
python3 scripts/manage.py up --connections --local-api
python3 scripts/manage.py verify
```

Откройте http://127.0.0.1:8501. Это адрес веб-интерфейса Streamlit, а не MongoDB. Внутри Docker дашборд обращается к `http://backend:8000`; только backend соединяется с `storage:27017`. QGIS продолжает использовать http://127.0.0.1:8000.

Для новой установки сначала выполните `python3 scripts/manage.py init`, затем команды выше. Контейнеры используют Linux; на Windows/macOS нужен Docker Desktop в режиме Linux containers.

## Загрузка Excel

Приложенный Excel не включён в публичный архив проекта. Сохраните свой `test_datasetA.xlsx`, например рядом с `docker-compose.yml`. На компьютере достаточно Docker и Python: библиотеки Excel и MongoDB устанавливаются в образ backend.

Соберите одноразовый импортёр (он использует тот же код backend и его технические учётные записи):

```bash
docker compose --profile import build excel-import
python3 scripts/import_excel.py test_datasetA.xlsx > excel-report-plan.json
```

Эта команда только читает и проверяет файл. Для записи:

```bash
python3 scripts/import_excel.py test_datasetA.xlsx --apply > excel-report-applied.json
python3 scripts/manage.py verify
```

Импорт может занимать несколько минут. Не закрывайте терминал. При ошибке команда завершится с ненулевым кодом. После успешного импорта нажмите «Обновить данные» в дашборде. Исходный файл всегда монтируется только для чтения. Не передавайте пароль в командной строке.

Импортёр сохраняет все непустые строки всех листов в `cases`, вместе с названием листа, номером строки, заголовками, исходными значениями/формулами и `imported_at`. Затем создаёт документы предметных коллекций. Пустые форматированные строки не считаются данными. `cases` здесь содержит и исходную широкую таблицу, и строки нормализованных листов: количество документов `cases` **не равно количеству пациентов**.

Повторная загрузка того же файла с тем же `--namespace test-dataset-a` не добавляет дубликаты. Существующие предметные документы не изменяются — в том числе правки из QGIS. Если импорт прервался, повторите команду: уже записанные данные сохранятся, недостающие будут добавлены. Это возобновляемый пакетный импорт, не единая транзакция. Для изменённого Excel исходные строки архивируются как новая версия по SHA-256; имеющиеся предметные документы остаются прежними. Обновление существующих пациентов этой командой намеренно не выполняется.

Другому независимому набору данных задайте свой `--namespace`. Его нужно сохранять при повторных загрузках. Числовые ключи Excel преобразуются в детерминированные ObjectId с учётом namespace и коллекции; ссылки преобразуются тем же способом. Готовые 24-значные ObjectId сохраняются.

## Что обнаружено в приложенном Excel

- `Instances`: 37 662 строки; `id_instance` преобразуется в `instance`.
- `Patient`: 37 662 строки. Возраст 0 сохраняется. Даты разбираются явно, без подстановки текущей даты.
- `Geodata`: 14 233 строки; координаты преобразуются в BSON double.
- `Location`: 14 256 строк; `address` вида `10;1` разбирается как `region;geodata`.
- `Region`: 160 строк, но только 61 уникальный ID. У неоднозначных регионов ссылка `municipality` опускается, все исходные варианты сохраняются в `cases`. Это согласованное с пользователем решение без изменения схемы.
- `Municipality`: 160 строк. Есть справочники Gender, Social_group, Severity, Influence.
- `Therapy`: 16 непустых строк без `_id`. Они сохраняются только в `cases`, поскольку нельзя надёжно определить идентификаторы терапии и связи. Номер строки не используется как вымышленный ключ.
- `Foci`, `Reception`, `Settlement`, `Street`, `Building`, `Placement` пусты.
- `medical_record` вида `;Спутник…` разбирается как `chronic_diseases;vaccine`; пустые части опускаются. BSON regex соответствует существующей модели, регулярные выражения при импорте не выполняются.
- Почти все значения пола получены в Excel формулой `RANDBETWEEN`. Используются сохранённые Excel результаты, без повторной генерации. Исходные формулы архивируются; эти данные нельзя трактовать как подтверждённые медицинские сведения.

Импорт не восстанавливает отсутствующие диагнозы из широкой исходной таблицы и не связывает медицинские записи с координатами по совпадению номеров строк. Для такого ETL нужно отдельное согласованное правило сопоставления. Некорректные поля и неразрешимые ссылки остаются в исходном архиве и отмечаются в отчёте; валидные части документов импортируются.

## Что показывает дашборд

В верхней части — точные количества документов по коллекциям, возраст и динамика обращений по всей базе. Группировки выполняет MongoDB. На отдельной карте показано до 5000 точек Geodata, независимо от наличия Foci. Это не карта подтверждённых заболеваний. Количество показанных точек и ограничение подписаны.

Нижний журнал содержит до 2500 последних обращений. Фильтры и показатели журнала относятся только к этой выборке; они не фильтруют верхнюю статистику или независимую карту Geodata. Без Therapy/Foci у обращения нет подтверждённого диагноза, тяжести или координат. Пустые поля больше не подменяются «лёгкой» тяжестью или фиктивным регионом. Подложка карты требует доступного интернета в браузере.

Сохранены вкладки приложенного дашборда, запросы и импорт GeoPackage. Их старые алгоритмы не переработаны в рамках Excel-импорта. Пространственные запросы требуют заполненных связей Foci → Location → Geodata; для нынешнего Excel пустой результат такого запроса ожидаем. Старые описания районов/алгоритмы GeoPackage имеют ограничения, описанные в `MERGE_NOTES.md`.

Выбор роли в старом дашборде — режим просмотра, а не полноценный вход пользователя. Поэтому порт 8501 публикуется только на 127.0.0.1. Не открывайте его в интернет без отдельной аутентификации и HTTPS. Токены и проверка владельца QGIS остаются без изменений.

## Файлы и функции

- `backend/app/modules/import_excel.py`: `oid` создаёт стабильные ключи; `convert` преобразует значения по `model.json`; `insert_missing` вставляет только отсутствующие документы; `execute` проверяет файл, помещает промежуточные данные в SQLite, архивирует строки и импортирует коллекции пакетами по 250. Без `store` выполняется только план. `main` — точка запуска внутри контейнера.
- `scripts/import_excel.py`: передаёт путь файла Docker без shell, монтирует файл read-only и вызывает backend-импортёр. Пароли берутся из существующей `.env`.
- `backend/app/modules/dashboard_stats.py`: `execute` считает общую статистику и возвращает ограниченную выборку координат через `/v1/statistics`.
- `backend/app/modules/export_data.py`: собирает журнал по связям, загружая только документы для текущих 2500 обращений. Ограничения гостевой роли сохраняются.
- `dashboard/app.py`: обращается только к backend, показывает общую статистику, карту и прежние рабочие вкладки.
- `dashboard/components/filters.py`: фильтрация по реальным полям `age`, `hospitalized`; возраст старше 100 больше не ломает slider.
- `dashboard/components/maps.py`: карта и текстовая карточка точки; внешние строки не интерпретируются как HTML.
- `dashboard/components/charts.py`: графики выбранных записей журнала.
- `docker-compose.yml`: подключение dashboard к app_net, опубликованный 8501, healthcheck Streamlit, отдельный одноразовый excel-import.
- `tests/integration/excel_dashboard.py`: проверяет полный приложенный набор, повторную загрузку, сохранение изменения точки, статистику API и исполнение интерфейса Streamlit. Запускается только в изолированной тестовой базе.

Пределы памяти: Storage 4 ГиБ, backend 256 МиБ, dashboard 512 МиБ, временный импортёр 768 МиБ — суммарно 5,5 ГиБ для этих контейнеров. SQLite и пакеты ограничивают память импорта; временные файлы импортёра находятся в tmpfs 256 МиБ. Память Docker Desktop, браузера и QGIS дополнительно расходуется на компьютере.

## Если страница не открывается

```bash
docker compose --profile connections ps -a
docker compose --profile connections logs --tail 100 dashboard backend
```

Dashboard должен быть healthy, в колонке ports — `127.0.0.1:8501->8501/tcp`. Если порт занят другим приложением, освободите его или измените левую часть привязки, например `127.0.0.1:8502:8501`, и пересоздайте dashboard. Адрес в браузере тогда http://127.0.0.1:8502. Для удалённого сервера используйте SSH-туннель или согласованную защищённую публикацию. `localhost` в браузере всегда означает компьютер, на котором открыт браузер.
