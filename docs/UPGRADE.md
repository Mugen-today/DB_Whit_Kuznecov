# Обновление существующей установки до 0.10.0

> Обновление 0.11.1: команды Excel/JSON и --dry-run/--apply описаны в [README](../README.md#import-version-20). Прежний плоский Excel — scripts/import_excel_records.py.


> Дополнение 0.11.0: [автоматический консольный импорт](AUTO_IMPORT_0110.md).


1. Зафиксируйте текущую версию, остановите пользовательские записи и сохраните
   резервную копию по [OPERATIONS.md](OPERATIONS.md).
2. Сохраните прежний .env, имена STORAGE_DATA_VOLUME/STORAGE_CONFIG_VOLUME,
   оба MongoDB-тома и нужный кеш незавершённого импорта. Не публикуйте секреты.
3. Замените файлы проекта. Оставьте прежний .env в корне. Не выполняйте init,
   не создавайте случайные новые имена вместо старых и не применяйте down -v.
4. Выполните из корня:

```powershell
py scripts/manage.py configure
py scripts/manage.py config --connections --local-api
py scripts/manage.py up --connections --local-api
py scripts/manage.py verify
py scripts/manage.py status
```

5. Переустановите dist/qgis_mongodb.zip, полностью перезапустите QGIS, заново
   подключитесь и проверьте backend_version=0.11.0. Перезагрузите Geodata и остальные слои.
6. Проверьте роли, счётчики и сохранённую geometry. Исходные файлы больше не нужны
   для запуска; сохранённые A+B, правки и маркеры cases не удаляются и не перезагружаются.

Дополнительный том `<STORAGE_DATA_VOLUME>_imports` хранит GPKG/SQLite-прогресс.
Он не заменяет прежние тома. configure дописывает только отсутствующие ключи,
не ротирует существующие пароли. При проблеме старого имени коллекции сначала
migrate-plan, затем отдельная административная миграция и обычный up; это не
автоматическое исправление всех произвольных схем.

Linux/macOS: python3 вместо py. Фактическая полнота проверки Docker/платформ
описана в [отчёте 0.10.0](../tests/OPTIMIZATION_0100.md).

Новые задания по умолчанию строгие. Существующие SQLite-задания получают
дополнительные колонки/таблицу отчёта без удаления подготовленных строк; прежний
режим остаётся строгим. Исторические задания до 0.9 не содержат новых квитанций
по документам, поэтому их старые счётчики нельзя считать полным аудитом задним числом.
Полные старые ошибки сверх прежнего ограничения восстановить невозможно.
Сохраняйте том импорта при обновлении. При изменении сопоставления/политики создаётся
новое задание. [Подробные правила и продолжение](GPKG_ERROR_POLICY_090.md).

В 0.10.0 запуск не выполняет seed. Для файлов вне проекта используйте явный импорт
по [новой инструкции](OPTIONAL_IMPORT_0100.md). Сохранённые старые задания совместимы.
