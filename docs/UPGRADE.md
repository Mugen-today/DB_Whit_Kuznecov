# Обновление существующей установки до 0.8.0

1. Зафиксируйте текущую версию, остановите пользовательские записи и сохраните
   резервную копию по [OPERATIONS.md](OPERATIONS.md).
2. Сохраните прежний .env, имена STORAGE_DATA_VOLUME/STORAGE_CONFIG_VOLUME,
   оба MongoDB-тома и нужный кеш незавершённого импорта. Не публикуйте секреты.
3. Замените файлы проекта. Оставьте прежний .env в корне. Не выполняйте init,
   не создавайте случайные новые имена вместо старых и не применяйте down -v.
4. Выполните из корня:

```powershell
py scripts/manage.py configure
py scripts/manage.py config --connections --local-api
py scripts/manage.py up --connections --local-api
py scripts/manage.py verify
py scripts/manage.py status
```

5. Переустановите dist/qgis_mongodb.zip, полностью перезапустите QGIS, заново
   подключитесь и проверьте backend_version=0.8.0. Перезагрузите Geodata и остальные слои.
6. Проверьте роли, счётчики и сохранённую geometry. Встроенные A+B не нужно удалять
   или вручную загружать заново: маркеры seed сохраняют исторические записи и правки.

Дополнительный том `<STORAGE_DATA_VOLUME>_imports` хранит GPKG/SQLite-прогресс.
Он не заменяет прежние тома. configure дописывает только отсутствующие ключи,
не ротирует существующие пароли. При проблеме старого имени коллекции сначала
migrate-plan, затем отдельная административная миграция и обычный up; это не
автоматическое исправление всех произвольных схем.

Linux/macOS: python3 вместо py. Фактическая полнота проверки Docker/платформ
описана в [отчёте 0.8.0](../tests/GPKG_BULK_080_VERIFICATION.md).
