# Version_21 / 0.11.2 — хранилище и устойчивость импорта

Основа: последняя доступная поставка этого чата 0.11.1. Отдельный архив локальной
Version_21 не предоставлялся. Рабочие данные и Docker volumes не подключались.

## Исправления

- Временная SQLite-база и полный отчёт перенесены из /tmp в существующий дисковый
  GPKG_UPLOAD_DIR (/var/lib/gis-imports). У импортёра /tmp ограничен tmpfs 256 МиБ;
  разжатый Excel, архив строк, журнал и отчёт могли превысить этот предел.
- Исходные строки промежуточного SQLite сжимаются zlib без потерь. При записи
  cases восстанавливается прежний BSON: менять клиентов/схему не требуется.
- Кеш staging SQLite ограничен 2 МиБ, это не предел всего процесса Python.
  В summary добавлен staging_bytes — размер основного файла после подготовки.
- ExitStack/closing закрывают соединение даже при сбое создания таблиц/индексов;
  source iterator и последний курсор закрываются до очистки временной папки.
  GPKG не остаётся открытым при ошибке нормализации или прерывании чтения.
- Выявленный при полном тесте NetworkTimeout: 3 секунды на операцию MongoDB
  оказались недостаточны для архива cases. CLI использует 30 секунд; backend
  без дополнительных переменных сохраняет прежние тайм-ауты. Права не изменены.
- Подтверждённые вставки учитываются после каждого пакета. При сбое status=failed,
  counts_are_confirmed_only=true: незавершённый пакет не объявляется успешным.
  Повтор insert-only дозаполняет недостающие ID, не удаляя прежние документы.
- Добавлены import_geojson.py/import_gpkg.py, сохранён единый import_data.py.
  Для плоских связанных записей автоматически создаются Location/Foci, geometry
  приводится существующим строгим конвертером модели без ложного unsupported type.
- Предупреждение дополнительного Excel-листа агрегируется по листу; строки
  архивируются все, количество показано в archive_only_rows. Это не потеря данных.

## Проверка

117 Python unit-тестов и три набора JavaScript mock-тестов прошли. Новые проверки:
дисковая папка staging, закрытие источника при ошибке, закрытое SQLite-соединение
GPKG после досрочного окончания генератора, прерывание после первых 250 из 500
Patient и повтор до ровно 500 без дублей. Проверено восстановление исходных raw
из сжатого staging в cases. Синтаксис Python/JS, JSON и ZIP плагина проверены.

Реальная MongoDB 8.0.34, аутентификация, rs0, полный bootstrap схемы/ролей. Два
предоставленных источника импортированы полностью и затем каждый повторён:

| Показатель после обоих источников | Количество |
|---|---:|
| Patient / Instances / Therapy / Foci | по 41938 |
| Geodata | 18509 |
| Location | 18532 |
| cases | 221420 |

Excel: 217144 исходные строки всех листов, включая дополнительный исходный лист;
нормализованных Patient/Instances — по 37662, Geodata — 14233. JSON B: 4276 строк,
Patient/Instances/Geodata — по 4276. Повторные inserted для всех коллекций и cases
равны нулю. Все Geodata имеют Point и координаты. Агрегациями проверено отсутствие
висячих присутствующих ссылок Therapy.patient, Instances.patient и Foci.location.
Общий preflight проверяет ссылки модели; неоднозначные/неразрешённые ссылки
исторического источника отражаются в отчёте и архиве, не выдумываются.

Для полного Excel измерен staging около 144,6 МБ (138 МиБ), для полного JSON —
27,4 МБ (26 МиБ). Эти числа не включают пиковый журнал, отчёт и накладные расходы
ОЗУ; они не являются требованием к минимальному свободному месту.

Повторно выполнен полный --dry-run обоих файлов: количества всех коллекций,
включая cases, до/после совпали. Записи не производились. Дополнительный лист
Excel корректно отражён в archive_only_rows (37662 строки), не дублирует Patient.

На отдельной синтетической фикстуре настоящие CLI-процессы проверили XLSX,
JSON, GeoJSON и GPKG: dry-run, apply, повтор с нулевыми вставками. Для GPKG
сформированы шесть связанных сущностей на строку. Проверены Point, основные FK,
переименование/удаление источника после окончания импорта. Воспроизводимый тест:
`tests/integration/disk_cli_modes.py` (только отдельная одноразовая БД!).
Агрегированные подтверждения — IMPORT_STORAGE_NATIVE_SUMMARY.txt.

## Границы

Полные образцы пользователя были только XLSX/JSON. GeoJSON/GPKG проверялись на
генерируемых структурах, произвольные неизвестные названия атрибутов не угадываются.
GeoJSON FeatureCollection по-прежнему загружается в память целиком; JSON-массив,
Excel и GPKG обрабатываются итеративно. Общего ограничения числа записей нет,
но объём клиентской/парсерной памяти и свободного диска конечен.

Docker daemon и Windows недоступны. Запуск внутри контейнерного tmpfs/Windows
не подтверждён: направление staging проверено тестом конфигурации/пути, реальные
приложения запускались нативно на Linux. WinError 32 отдельно на Windows не
воспроизводился; закрытие соединений подтверждено unit и Linux rename/delete.
Права, model.json, имена volumes и конфигурация Compose сохранены.

Первый полный прогон выявил NetworkTimeout на старом трёхсекундном лимите.
После исправления финальный прогон завершился успешно. На физически заполненном
диске даже дисковое staging остановится: README содержит диагностику без удаления
MongoDB volumes. При позднем сбое подтверждённые пакеты остаются, общей транзакции
файла/автоматического отката нет. Исходные файлы открываются только для чтения.
