# Проверка GIS-MongoDB 0.8.0

11.11.2026. Основа — поставка 0.7.1. Проверки с записью выполнялись только в
одноразовых базах, рабочие Docker volumes не подключались.

## Подтверждено

- 88 unit-тестов Python; три набора JavaScript mock-тестов; синтаксис Python/JS и JSON.
- Настоящие MongoDB 8.0.34 с аутентификацией/rs0, backend, PyQGIS 3.40.6 offscreen.
- Полная холодная загрузка обоих встроенных источников, без использования seed-marker
  и без восстановления готового снимка для проверки исходных данных.
- Все 18509 Geodata после seed имеют сохранённые geometry.type=Point и две координаты.
- У четырёх документов отдельно смоделированы geometry=null, {}, пустая строка,
  Point с пустым coordinates. Восстановление записало правильные geometry в MongoDB;
  прежние значения сохранены, ID и контрольный дополнительный атрибут не изменились.
  Повтор процедуры не меняет количество документов.
- Все 17 коллекций полностью загружены в QGIS; все Geodata имеют непустые Point
  EPSG:4326; экспорт 17 коллекций в GPKG и повторное открытие подтвердили количества.
- Сохранены обычные правки QGIS, контроль ревизий, переключение ролей, права гостя,
  пользовательские запросы консоли и полный dashboard аналитика.
- Через настоящий диалог QGIS передан GPKG **43589632 байта / 5003 строки**,
  превышающий старые ограничения 32 МиБ и 1000 строк. Неиспользуемый BLOB в таблице
  не включался в читаемые атрибуты. Все 5003 Patient и 5003 Geodata записаны,
  Instances не создавалась. Количества сверены с MongoDB.
- Диалог закрыт после первых подтверждённых строк. Новое окно продолжило сохранённое
  задание с серверной позиции. Итог — ровно 5003 Patient, без пропусков и дублей.
  Повторное продолжение завершённого задания не добавляет документов.
- В том же большом файле обязательное поле строки 5003 сделано пустым. После полной
  пакетной проверки импорт запрещён; количество документов не увеличилось.
- Отдельное задание на 1003 строки: после первой страницы проверки backend полностью
  остановлен и запущен заново. Сохранились 250 проверенных строк. После записи первых
  25 строк backend перезапущен ещё раз. Импорт завершён — ровно 1003 новых Geodata.
- Unit: потеря подтверждения после условного MongoDB commit, повтор пакета,
  составные PK, чужой владелец, несовпадающий повтор upload chunk, пустой/ошибочный CRS,
  невалидные обязательные поля/FK/типы, поздняя ошибка не допускают потери/пропуска строк.
- Unit: страница, ограниченная байтами раньше 250 строк, не считается концом таблицы.
  Аналогично legacy next_offset соответствует реально импортированным строкам,
  а не теоретическому размеру пакета. Все строки доходят до конца.
- Unit: очистка истёкшего служебного кеша сохраняет активные загрузки и посторонние файлы.
- Настоящий Qt-тест: устаревшая проверка после смены полей не включает кнопку;
  полный текст длинной ошибки остаётся доступен.
- Compose config проверен с connections/import и local-api. Имена двух прежних томов
  и существующие секреты сохранены; новый import staging монтируется отдельным дисковым томом.
- model.json, test_datasetA.xlsx, testB_normalized.json побайтно совпадают с 0.7.1.

## Практические пределы

Docker socket недоступен (operation not permitted). Образы и контейнерная сеть
фактически не запускались; использовались отдельные процессы. Windows/macOS и полная
QGIS 3.28 не запускались. Общего программного лимита строк/байтов нового файла нет,
но нужны свободный диск, время и соблюдение ограничений формата/атрибутов.
Транзакции охватывают строку, а не весь файл; применённые строки сохраняются при сбое.
Рабочие MongoDB данные и volumes не удалялись и не перезаписывались.

Сетевые проверочные сценарии в tests/integration содержат тестовые вставки/правки —
запускайте их только против отдельной одноразовой базы с A+B. Основные новые сценарии:
bulk_qgis.py, bulk_resume_http.py; автономные регрессии — tests/unit/test_gpkg_batches.py.
