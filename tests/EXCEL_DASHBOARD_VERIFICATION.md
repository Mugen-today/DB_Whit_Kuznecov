# Проверка Excel и дашборда

Проверяемый источник: `test_datasetA.xlsx`, SHA-256 `a576414b4d5157c3a209edf94be89c8c2e6de102d9cc20ad0c842c4856fd7fce`.

Два независимых успешных прогона на свежих тестовых базах. Каждый прогон включал полный импорт и повторную загрузку: 144,9 с и 126,9 с соответственно (локальная среда, не производительный бенчмарк).

## Выполненные проверки

- 41 Python unit-тест, включая преобразования Excel: успешно, без пропусков при установленных зависимостях backend.
- Три существующих JavaScript набора проверок: успешно.
- Проверка синтаксиса Python, JSON, структуры поставки: успешно.
- Настоящий Docker Compose v2 проверил конфигурацию services/profiles/volumes/ports.
- Настоящий Streamlit 1.51.0 ответил HTTP 200 на корневой странице порта 8501 и `ok` на `/_stcore/health`.
- Полный XLSX импортирован в отдельную настоящую MongoDB 8.0.34 с аутентификацией и валидаторами. Использованы PyMongo 4.19.0, openpyxl 3.1.5, pandas 2.3.3, pydeck 0.9.1.
- Проверены BSON-типы идентификаторов, ссылки Patient/Gender, сохранение вакцинации в соответствии с моделью, точные количества документов.
- Повторный импорт добавил 0 документов во все коллекции. Внесённая между импортами правка Elevation осталась без изменений.
- Backend вернул общую статистику по полным коллекциям; суммы распределений возраста и дат совпали с 37 662 записями. Выборка карты ограничена 5000 точками, журнал — 2500 обращениями.
- Streamlit AppTest исполнил настоящий код интерфейса с настоящим backend/MongoDB в режимах reader и guest без исключений и сообщений об ошибках подключения.

Количества результата приведены в `EXCEL_IMPORT_REPORT.json`. В нём нет самих медицинских записей, только количества и диагностические номера строк.

## Ограничения проверки

MongoDB, backend и Streamlit запускались отдельными локальными процессами. Docker daemon и Linux container runtime в этой среде недоступны; реальное создание контейнеров, применение cgroup-лимитов и публикация Docker-порта на компьютере пользователя здесь не проверены. Для локального MongoDB использована адаптация обнаружения CPU к ограничениям тестовой среды; код поставки её не содержит. Проверка DNS имён Docker не подменяет проверку на машине пользователя: в локальном тесте использовались loopback-адреса.

AppTest проверяет выполнение интерфейса и компоненты, но не является ручной проверкой отрисовки картографической подложки в браузере. Для подложки требуется доступ браузера к внешнему картографическому сервису.

Проверки не подключались к рабочей базе пользователя и не меняли её. Старые сценарии GeoPackage/районных запросов имеют ограничения из `docs/MERGE_NOTES.md`; полный ETL для них этой проверкой не подтверждён. Код плагина QGIS в этой редакции сохранён.
