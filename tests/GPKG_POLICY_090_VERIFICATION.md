# Проверка GIS-MongoDB 0.9.0

14.11.2026. Основа — приложенный пользователем `GIS-MongoDB(1).zip`.
Запись выполнялась только в одноразовые тестовые базы. Существующие Docker volumes
не подключались, не очищались и не переименовывались.

## Выполненные проверки

- **101 Python unit-тест**: прошли. В том числе классификация критических/строчных
  ошибок, строгий и частичный режимы, неизвестная CRS, типы и обязательные значения,
  неверная геометрия, исключение преобразования CRS как ошибка строки, права,
  остановка на инфраструктурном сбое, повтор той же строки, отсутствие фиктивных
  значений, полный отчёт из 305 ошибок, необязательный NULL как предупреждение.
- Проверена миграция старого SQLite-задания: исходные подготовленные строки
  сохранены, повторное чтение отчёта не дублирует исторические ошибки.
- Три набора JavaScript mock-тестов: bootstrap/роли, миграции, verify — прошли.
  Проверены AST Python, синтаксис JS и JSON.
- **Настоящие MongoDB 8.0.34, rs0, аутентификация, Python backend и QGIS 3.40.6**
  (PyQGIS/Qt offscreen): интеграционные сценарии прошли.
- Холодная загрузка обоих встроенных источников A+B: все **18 509 Geodata**
  получили сохранённые `geometry.type=Point` и координаты. Варианты null, {},
  пустая строка и Point с пустыми координатами восстановлены штатным скриптом;
  прежние значения, ID и контрольный дополнительный атрибут сохранены.
- Полная пагинация и загрузка всех 17 пользовательских коллекций в QGIS,
  непустая Geodata.geometry, экспорт 17 коллекций в GPKG и повторное открытие
  с равными количествами; правки атрибутов/геометрии синхронизированы с MongoDB.
- Смена пользователя/гостя/аналитика обновляет права и режимы слоёв; пользовательский
  текст find/aggregate/countDocuments/distinct, regex, BSON, пространственные
  операции и ошибки консоли проверены через HTTP и настоящий QGIS.
- Dashboard проверен через Streamlit для reader/user/guest: вкладки, фильтры,
  графики и журнал. Полная аналитическая выборка reader сохранена.
- GeoPackage **43 589 632 байта, 5003 строки** загружен настоящим диалогом QGIS:
  передача частями, пакетная проверка/запись, продолжение после закрытия окна,
  повтор без дубликатов. Ошибка в строке 5003 в строгом режиме запрещает все записи.
- Отдельное задание на 1003 строки пережило реальный перезапуск backend во время
  проверки и второй перезапуск после первых 25 записанных строк; пропусков/дублей нет.
- Реальный сценарий политики: 4 строки с одной ошибкой Patient.age. Strict —
  0 записей; partial — 3 строки, 6 документов Patient+Geodata, 1 явное отклонение.
  Исходный GPKG сохранил SHA256, Instances не изменилась. Ссылки на недоступного/
  отсутствующего пациента отклонены по строкам, фиктивные ссылки не создавались.
- Повтор этого файла новым заданием: 6 подтверждённых, 0 новых, 6 повторно
  использованных документов. После **реального MongoDB commit** смоделирована
  потеря подтверждения AutoReconnect: задание остановилось до продвижения позиции;
  повтор завершился без дублей и с точным учётом 8 созданных документов.
- Настоящий Qt-диалог: **243 строки**, strict блокирует запись; partial принимает
  **121** строку / **242** документа и отклоняет **122**. Сохранённый CSV содержит
  все 122 ошибки с верными номерами, Patient.age, этапом и причиной — сверх
  ограничения предварительного просмотра 100 ошибок.
- Исходные `data/*`, `storage/*`, `model.json` и все Compose-файлы побайтно
  совпадают с приложенной версией. ZIP плагина проверен по CRC и побайтно сопоставлен
  с текущими исходниками плагина.
- Docker Compose config с профилями connections/import и local API проходит.

## Границы результата

Полный запуск контейнеров в этой среде **не проверен**: Docker daemon socket
недоступен (`operation not permitted`). Вместо этого приложения, MongoDB, bootstrap,
провизионирование, индексы, seed, HTTP и QGIS проверялись нативно на временных данных.
После обновления своей установки выполните штатные `manage.py verify/status`.

Строгий режим гарантирует нулевую запись при ошибке полной предварительной
проверки и остановку при ошибке записи. Транзакция охватывает связанную строку,
а не весь файл: уже подтверждённые строки при позднем сбое остаются в БД.
Автоматического удаления этих документов/общего отката файла нет.

Исторические задания до 0.9 не содержали новых квитанций по документам; их
старые счётчики не восстанавливаются задним числом. Все старые ошибки сверх
прежнего лимита восстановить из отсутствующих данных невозможно.

Новый интеграционный код находится в `tests/integration/gpkg_policy_http.py` и
`gpkg_policy_qgis.py`. Запускайте его только в выделенной одноразовой тестовой БД:
эти сценарии создают тестовые документы. Обычный импорт не удаляет исходные данные.
