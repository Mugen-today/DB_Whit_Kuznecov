# Проверка версии 0.7.1

11.11.2026. Проверена актуальная поставка 0.7 и выполнены три целевых исправления.
Все проверки с записью использовали отдельную одноразовую БД. Рабочие данные
и Docker volumes не подключались и не удалялись.

## Успешные проверки

- 79 Python unit-тестов; три JavaScript-набора; Python/JS syntax, JSON.
- Настоящая MongoDB 8.0.34 с аутентификацией и rs0; backend и PyQGIS 3.40.6 / Qt offscreen.
- Полная пагинация всех 17 коллекций; количества равны countDocuments.
- Все записи Geodata тестового набора имеют непустой Point; CRS слоя EPSG:4326,
  координаты лежат в допустимом диапазоне.
- Все 17 коллекций экспортированы в один GeoPackage, повторно открыты OGR;
  количества записей совпадают. Остальные 16 коллекций продолжают загружаться.
- Атрибуты/координаты отредактированы в QGIS; MongoDB подтверждает изменения;
  невалидный возраст отвергается с сохранением буфера.
- Пользовательский текст введён в настоящее окно консоли, выполнен кнопкой:
  db["Patient"].find, db.getCollection("Geodata").find с /regex/i,
  countDocuments, aggregate/toArray, distinct. Получены действительные ответы MongoDB.
- Синтаксическая ошибка и запрещённый $out показаны в консоли;
  guest не получает закрытую Social_group через новый синтаксис.
- В окне импорта выбраны файл/поля. Без нажатия ручной проверки кнопка загрузки
  автоматически активировалась. Импортированы только Patient и Geodata;
  Instances не создавалась. Необязательный NULL Elevation принят.
- Пропуск Patient.reg_date немедленно блокирует кнопку; сервер объясняет причину.
  После восстановления поля автоматическая проверка снова разрешает импорт.
  Повтор не создаёт дополнительных Patient.
- GPKG с несовпадающими CRS, неверными FK/типами, недостающими обязательными
  значениями, подменой имени таблицы и гостевой записью отклонён.
- Unit: все обязательные атрибуты выбранного Patient равны NULL — импорт не
  превращается молча в импорт одной Geodata.
- Unit: пустые строки и пробелы необязательного числового поля пропускаются,
  значение 0 не пропускается. Требования UI объединяют model.json и бизнес-правила.
- Отдельный Qt-тест: устаревший ответ проверки после изменения полей не включает
  загрузку; ошибка большого размера сохраняет полный текст и доступ к повторной проверке.
- Декодер проверен с имитацией API без geometryFromGeoJson: Point читается корректно.
  Полная QGIS 3.28 не запускалась; совместимый путь API проверен в QGIS 3.40.
- Dashboard: все три роли, полный счётчик аналитика, JSON/XML-консоль, вкладки,
  фильтры/графики/журнал без ошибок. Смена прав user/guest/analyst сохранена.
- /v1/session сообщает backend_version 0.7.1; проверено unit-тестом.

## Сохранность и ограничения

model.json, оба источника и Compose-файлы побайтно не изменены относительно 0.7.
Архитектура MongoDB → backend → QGIS/dashboard, схема связей, права и тома сохранены.
Конфигурация и seed не заменяют старые секреты/данные. В поставке нет рабочего .env.

Docker socket недоступен (operation not permitted). Запуск/сборка контейнеров
и сеть между ними в этой среде не подтверждены; использовались отдельные процессы.
Windows/macOS и полная QGIS 3.28 не запускались. Геометрии исторических строк
нормализуются только для ответа API; исходная БД при чтении не меняется.
Предельный размер файла/число строк GPKG и транзакции на строку сохранены.

Воспроизводимые сценарии: tests/integration/hotfix_workflows.py,
hotfix_ui_state.py, comprehensive_http.py, comprehensive_qgis.py.
Все сетевые сценарии запускайте только против одноразовой тестовой БД с A+B:
они содержат проверочные вставки и правки. hotfix_ui_state.py не использует БД.
