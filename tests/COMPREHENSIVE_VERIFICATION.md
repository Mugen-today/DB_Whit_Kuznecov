## Обнаруженные и устранённые проблемы

- Общий предел страниц заменён обходом курсоров; число документов не усечено.
- Таймаут клиента MongoDB 3 секунды мешал lookup: для консоли заданы отдельные сроки.
- Повторное определение QGIS-типа поля для каждой строки давало квадратичный обход.
  Тип теперь вычисляется один раз; отдельная таблица 30000 строк строилась за 0,25 с.
- Python-обёртки ранее загруженных слоёв теряли обработчики: ссылки теперь удерживаются.
- setAllowCommit отсутствует в Python API QGIS. Сохранение защищает тонкий provider
  поверх прежнего memory cache: непринятые backend изменения не фиксируются локально.
- Прежние идентификаторы int/string и дополнительные BSON-значения не ломают страницы.

## Пределы подтверждения

Docker socket недоступен: запуск/сборка образов и сеть между контейнерами в этой
среде не подтверждены. Использовались отдельные процессы MongoDB/backend и
Qt offscreen. Compose config не заменяет полноценный Docker-прогон.
Windows/macOS и ручная браузерная отрисовка внешних карт/WebGL не проверялись.

Сценарии comprehensive_http.py/comprehensive_qgis.py и gpkg_rejections.py создают
тестовые документы: запускайте их только против отдельной одноразовой БД с A+B.
Обычные manage.py test и check_project.py не используют рабочую БД.
manage.py integration требует Docker и использует собственный случайный проект/тома.

Выгрузка без общего лимита требует памяти клиента. GPKG-импорт сохраняет защитные
ограничения 32 МиБ и 1000 строк на таблицу, 2D Point/атрибуты; транзакция на строку.
Правки слоя отправляются транзакционными пакетами по 200, не одной транзакцией на
весь слой. Memory cache нужно заново загрузить после открытия сохранённого QGIS-проекта.
