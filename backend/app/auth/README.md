# Ролевой доступ

`ownership.py` — внутренний слой проверки владельца. Principal передаёт только будущая серверная аутентификация; принимать user_id/role клиента без проверки нельзя. Пока login/API отсутствуют, эти функции не опубликованы в HTTP.

Пользователь видит и меняет только собственные модельные документы по `_owner_id`. Записи без владельца не назначаются автоматически и недоступны обычному пользователю. Исходная cases через этот слой не редактируется. Guest читает разрешённые коллекции через отдельного MongoDB-пользователя guest; четыре запрещённые коллекции не доступны ни в Python, ни в MongoDB.

Роль MongoDB gis_user ограничивает действия на коллекциях, но НЕ обеспечивает изоляцию документов по владельцу. app_user — техническая учётная запись backend; её пароль нельзя выдавать пользователю или использовать как пользовательский вход в Compass. Подключение app_user напрямую обходит ownership.py.

Администратор работает через отдельно защищённый административный путь (storage_admin/root в admin). Полноценный HTTP-вход администратора, пользователя и гостя ещё не реализован. gis_admin — назначаемая административная MongoDB-роль с наследованием root.


В QGIS-версии маршруты /v1/qgis/points используют серверное сопоставление Bearer-токенов с фиксированными user/guest. Обновление Geodata проверяет _owner_id и qgis_revision атомарно. Подробности и ограничения единой идентичности токена приведены в docs/QGIS.md.
